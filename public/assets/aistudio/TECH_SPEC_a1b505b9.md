1. System Architecture Overview
Project Cirque implements an asymmetric cloud-to-edge spatial intelligence architecture:


1. Cloud Compilation Plane (Google Cloud Run + AlloyDB with PostGIS/pgRouting + GCS + Cloud CDN):
   * Ingests raw vector geometries from OpenSkiData and OpenStreetMap Overpass API, resort bounds from Skimap.org, on-mountain dining/amenities (Big Sky Mountain Dining), and USGS 3DEP DEMs.
   * Cloud Run Jobs (cirque-compiler) execute topological validation and serialize mountain networks into atomic .sqlite packages.
   * Cloud Run telemetry workers poll live operational status via Liftie to serve dynamic delta overlays.
   * Packages and distributes versioned mountain bundles and quantized Gemma model packs via Cloud Storage and Cloud CDN.
2. Edge Execution Runtime (iOS + Local SpatiaLite + On-Device Gemma + SiriKit):
   * Runs 100% offline in airplane mode.
   * Uses on-device quantized Gemma (2B/4B) via Core ML/Metal to parse natural-language voice prompts into structured intent schemas.
   * Filters open venues by time-of-day before executing multi-target pathfinding for amenity queries (e.g., quick lunch, warming huts, ski patrol).
   * Executes Dijkstra/A* pathfinding across local SQLite graph tables.
   * Emits turn-by-turn navigation via AVSpeechSynthesizer to Bluetooth helmet audio.

2.2 Upstream Open Ski Data & API Contracts
The data ingestion pipeline consolidates five vetted open ski map API and telemetry sources:
Primary Topology & Geometry (OpenSkiData & OpenSkiMap):
Ingests normalized GeoPackage (openskidata.gpkg) and GeoJSON extracts generated by openskidata-processor.
Provides pre-sanitized feature collections for ski areas, runs, and lifts with pre-computed slope gradients and canonical IDs.
REST API reference at api.openskimap.org for entity resolution.
Ad-Hoc & Targeted Extraction (OpenStreetMap Overpass API):
Primary endpoint: https://overpass-api.de/api/interpreter
Queries OSM winter sport primitives: piste:type=* (downhill, nordic, skitour), piste:difficulty=* (novice, easy, intermediate, advanced, expert, freeride), piste:grooming=*, and aerialway=* (chair_lift, gondola, cable_car, t-bar).
Serves as the fallback for real-time bounding box extraction and changeset verification.
Resort Directory & Boundary Metadata (Skimap.org):
REST endpoint: https://skimap.org/skiareas/view/{id}.json
Supplies official resort boundaries, sub-zone delineations, and high-resolution scanned trail map assets for visual fallback.
Live Operational Telemetry (Liftie & ski-lift-status):
Scrapes real-time lift and run operational status (open, closed_patrol, wind_hold, mechanical_hold) at 5-minute intervals.
Adapts live status payloads into SQLite dynamic_status_overlay records mapped by lift and trail slug.
Visual Validation & Cartographic QA (OpenSnowMap):
Slippy map tile endpoints (https://tiles.opensnowmap.org/pistes/{z}/{x}/{y}.png and base_snow_map/{z}/{x}/{y}.png) used in web inspection tools to visually audit topological junction alignment against satellite and hillshaded relief.

2.3 Relational Graph DDL (topology.sqlite)
The compiled SQLite schema must strictly implement the following structure:




PRAGMA foreign_keys = ON;
PRAGMA journal_mode = WAL;


-- 1. NODES: Intersection junctions, lift base/top terminals, POIs
CREATE TABLE nodes (
    node_id TEXT PRIMARY KEY,
    name TEXT,
    lat REAL NOT NULL,
    lon REAL NOT NULL,
    elevation_m REAL NOT NULL,
    node_type TEXT CHECK(node_type IN ('trail_junction', 'lift_base', 'lift_top', 'poi', 'summit', 'village')),
    poi_category TEXT CHECK(poi_category IN ('restaurant_sitdown', 'cafeteria', 'warming_hut', 'patrol', 'restroom', NULL))
);


-- 2. EDGES: Directed ski pistes and aerial lifts
CREATE TABLE edges (
    edge_id TEXT PRIMARY KEY,
    source_node TEXT NOT NULL REFERENCES nodes(node_id),
    target_node TEXT NOT NULL REFERENCES nodes(node_id),
    type TEXT NOT NULL CHECK(type IN ('piste', 'lift')),
    name TEXT NOT NULL,
    difficulty TEXT CHECK(difficulty IN ('novice', 'intermediate', 'advanced', 'expert', 'freeride', 'lift')),
    grooming TEXT CHECK(grooming IN ('groomed', 'backcountry', 'mogul', NULL)),
    length_m REAL NOT NULL,
    vertical_diff_m REAL NOT NULL, -- Negative for downhill pistes, Positive for lifts
    average_pitch_pct REAL NOT NULL,
    base_cost_seconds REAL NOT NULL,
    FOREIGN KEY(source_node) REFERENCES nodes(node_id),
    FOREIGN KEY(target_node) REFERENCES nodes(node_id)
);


-- Spatial and routing indexes
CREATE INDEX idx_edges_source ON edges(source_node);
CREATE INDEX idx_edges_target ON edges(target_node);
CREATE INDEX idx_edges_type_diff ON edges(type, difficulty);
CREATE INDEX idx_nodes_coords ON nodes(lat, lon);
CREATE INDEX idx_nodes_poi ON nodes(poi_category);


-- 3. EPHEMERAL DYNAMIC OVERLAY (Attached or In-Memory)
CREATE TABLE dynamic_status_overlay (
    edge_id TEXT PRIMARY KEY REFERENCES edges(edge_id),
    status TEXT NOT NULL CHECK(status IN ('open', 'closed_patrol', 'wind_hold', 'mechanical_hold')),
    effective_grooming TEXT CHECK(effective_grooming IN ('groomed', 'ungroomed', 'powder', 'moguls')),
    last_updated_epoch INTEGER NOT NULL
);
-- 4. MOUNTAIN SERVICES: On-mountain dining, grab-and-go, warming huts, patrol
CREATE TABLE mountain_services (
    service_id TEXT PRIMARY KEY,
    node_id TEXT NOT NULL REFERENCES nodes(node_id),
    name TEXT NOT NULL,
    category TEXT NOT NULL CHECK(category IN ('quick_snack', 'cafeteria', 'sit_down', 'bar', 'warming_hut', 'patrol', 'restroom')),
    service_speed TEXT CHECK(service_speed IN ('grab_and_go', 'counter_service', 'table_service', NULL)),
    open_time_local TEXT NOT NULL,                   -- 'HH:MM' (e.g. '11:00')
    close_time_local TEXT NOT NULL,                  -- 'HH:MM' (e.g. '15:30')
    requires_reservation INTEGER NOT NULL DEFAULT 0, -- 1 = Yes, 0 = No
    price_tier TEXT CHECK(price_tier IN ('$', '$$', '$$$', '$$$$', NULL)),
    is_ski_in_only INTEGER NOT NULL DEFAULT 1,
    daily_status TEXT NOT NULL DEFAULT 'open' CHECK(daily_status IN ('open', 'closed_weather', 'closed_seasonal'))
);


CREATE INDEX idx_services_lookup ON mountain_services(category, service_speed, daily_status);
CREATE INDEX idx_services_node ON mountain_services(node_id);
2.4 Directed Acyclic Graph Rules
2. Piste Edges: Must be strictly directed downhill (source_node.elevation_m > target_node.elevation_m). Any flat runout (< 0.5% grade) must have bidirectional edges with a heavy cost penalty for uphill traversal.
3. Lift Edges: Must be strictly directed uphill (source_node.elevation_m < target_node.elevation_m). base_cost_seconds = calculated lift transit time (nominal lift speed / cable length).
4. Connectivity Guarantee: Lift top terminal nodes must connect to trail head nodes within a 25-meter euclidean radius via virtual walk/skate edges (length_m <= 25, cost = 30s).
5. POI Snapping & Service Access: Mountain service entities are snapped to the nearest graph node or connected via virtual pedestrian walk edges (length_m <= 50, cost = 45s). Virtual edges are marked bidirectional with flat elevation grade.

7. Cloud Deployment, Storage & CI/CD Specification
7.1 Serverless Serving & Compute Architecture (Google Cloud Run)
Project Cirque deploys its backend plane onto Google Cloud Run to achieve zero-idle cost, automated scaling, and isolated batch job execution:
* `cirque-api` (Cloud Run Service):
   * Lightweight Go/FastAPI service exposed via Google Cloud HTTPS Load Balancing.
   * Endpoints:
      1. GET /v1/resorts: Lists available resort packs, versions, and geographical bounding boxes.
      2. GET /v1/resorts/{id}/manifest: Returns SHA-256 checksums, schema versions, and signed download URLs.
      3. GET /v1/resorts/{id}/overlay: Serves daily operational lift/run status and effective grooming diffs (cached for 180s).
* `cirque-compiler` (Cloud Run Job):
   * High-memory containerized job (16 vCPU, 32GB RAM) triggered by Cloud Scheduler (weekly or post-OSM updates).
   * Connects to AlloyDB via Serverless VPC Access, executes spatial graph compilation, samples DEM elevations, and uploads compiled .mountain packages to GCS.
* `telemetry-sync` (Cloud Run Job / Worker):
   * Triggered every 5 minutes during operating hours (08:00–17:00 MST) via Cloud Scheduler cron (*/5 8-17 * * *).
   * Scrapes Liftie and resort operational feeds to produce ephemeral JSON delta updates.
7.2 Storage Architecture & Distribution (GCS + Cloud CDN)

7.3 Database Architecture
* Cloud Compilation Plane: AlloyDB for PostgreSQL (or Cloud SQL Enterprise) with PostGIS and pgRouting extensions. Used exclusively for heavy geometric operations, topological network creation, and graph integrity auditing.
* Ephemeral Telemetry Store: Cloud Memorystore (Redis) or Cloud Run in-memory cache for live lift statuses and recent scrape diffs.
* Client / Edge Runtime: Embedded SQLite 3 operating in Write-Ahead Logging (WAL) mode with custom spatial B-tree indexes, ensuring 100% offline querying without network calls.
